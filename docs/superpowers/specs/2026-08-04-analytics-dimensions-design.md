# Analytics 统计维度扩展设计

## 背景

当前 Analytics 页面已经支持时间范围、时间桶、协议、模型、站点和 Access Key 筛选，并展示请求趋势、成功/失败趋势、Token 趋势、耗时趋势、回退趋势、缓存命中率、站点分布和模型分布。

使用日志已经保存了来源、协议、站点、Access Key、模型、状态、错误信息、流式状态、重试和回退等数据，但 Analytics 尚未充分聚合这些字段。此次扩展不改变现有核心看板的默认布局和统计口径，而是在其基础上增加统一的细分分析能力。

## 目标

- 保留现有 8 个核心图表及其默认展示方式。
- 增加来源、Access Key、协议、失败原因、HTTP 状态码、回退链路和延迟分位数分析。
- 复用现有 `Source` 字段和 Usage Logs 中已有的来源分类，不重新定义来源体系。
- 支持来源、Access Key、协议、站点和模型的点击联动筛选。
- 统一所有分析维度的请求去重和最终结果统计口径。
- 保证旧日志兼容，并避免返回密钥、请求体、响应体或认证信息。
- 不增加导出功能；Analytics 只负责统计和联动分析，具体请求排障继续使用 Usage Logs 和 Developer Invocations。

## 非目标

- 不把 Analytics 改造成可自由配置的通用数据透视表。
- 不移除或隐藏现有站点分布、模型分布和趋势图表。
- 不在第一版打开请求正文、响应正文或完整错误文本下钻。
- 不返回 Access Key 明文、上游 API Key 或认证 Token。
- 不增加 CSV、JSON 或其他格式的导出接口。

## 设计方案

### 核心看板

现有以下图表保持不变：

- 请求趋势
- 成功/失败趋势
- Token 趋势
- 耗时趋势
- 回退趋势
- 缓存命中率
- 站点分布
- 模型分布

现有筛选条件继续保留：

- 时间范围
- 时间桶
- 协议
- 模型
- 站点
- Access Key

新增来源筛选，来源值直接使用日志中的 `Source`：

- `proxy`
- `chat`
- `claude-code`
- `codex`
- `open-code`
- `zcode`
- `detection-manual`
- `detection-task`

来源中文名称继续复用 Usage Logs 页面现有映射。

### 细分分析区域

在现有核心图表之后增加一个统一的细分分析区域，以 Tab 切换维度：

- 来源
- Access Key
- 协议
- 失败原因
- HTTP 状态码
- 回退链路
- 延迟分位数

默认打开“来源”。站点分布和模型分布仍保持原来的独立图表，不迁移到该 Tab 区域。

来源、Access Key、协议、失败原因和状态码使用统一表格结构：

- 维度名称
- 请求数
- 成功数
- 失败数
- 成功率
- Token 总量
- 平均总耗时
- 回退请求数

默认按请求数降序排列，支持表头排序。维度项同时保存稳定的 `key` 和展示用 `label`，避免中文名称变化或名称重复影响联动筛选。

### 统计口径

- 以 `RequestId` 代表一次完整请求。
- 同一请求的多条尝试记录不能重复计入请求数。
- 最终日志决定最终成功或失败。
- Token、总耗时和首字延迟使用最终日志。
- 回退指标使用同一请求的完整尝试链路，并按 `RequestId` 去重。
- 最终失败分析只统计最终结果失败的请求。
- 中间尝试失败但最终回退成功的请求不计入最终失败。
- 回退触发原因与最终失败原因分开统计。

### 失败原因与状态码

为避免长期依赖自由文本解析，日志模型和日志写入模型增加结构化字段：

- `HttpStatusCode`：可为空的 HTTP 状态码。
- `ErrorCategory`：稳定的错误分类代码。

错误分类包括：

- `stream-interrupted`：流式中断
- `timeout`：超时
- `authentication`：认证失败
- `rate-limit`：限流
- `model-not-found`：模型不存在
- `upstream-error`：上游服务异常
- `network-error`：网络错误
- `other`：其他失败

分类优先级固定：流式中断、超时、认证失败、限流、模型不存在、上游服务异常、网络错误、其他失败。

新日志优先在写入时保存结构化分类和状态码。历史日志没有新字段时，在统计阶段基于已有 `Status`、`ErrorMessage` 和流式状态做兼容分类。Analytics 只返回分类和状态码统计，不返回完整错误文本。

### 回退链路

使用已有 `RequestId`、`TargetSiteId`、`AttemptIndex`、`RetryCount`、`FallbackTriggered` 和最终结果字段，增加：

- 回退请求总数
- 回退后成功数
- 回退后失败数
- 回退成功率
- 平均尝试次数
- 首次站点到最终站点的链路排行
- 首次模型到最终模型的链路排行

链路表的主要列为：

- 首次站点
- 最终站点
- 请求数
- 回退成功率
- 平均尝试次数

链路分析只返回聚合结果，不返回请求正文或上游认证信息。

### 延迟分位数

在现有平均耗时基础上增加：

- 总耗时 P50、P95、P99
- 首字延迟 P50、P95、P99

同时保留平均总耗时和平均首字延迟。分位数基于当前筛选后的最终请求计算，并返回样本数。样本较少时显示实际计算结果，不填充或伪造稳定性数据。

### 联动筛选

以下维度支持点击后联动整个 Dashboard：

- 来源
- Access Key
- 协议
- 站点
- 模型

点击行为：

- 点击未选中项：加入对应筛选。
- 点击同一项：取消对应筛选。
- 点击同一维度的其他项：替换该维度筛选。
- 顶部显示当前生效筛选标签。
- 支持删除单个标签和重置全部筛选。

失败原因、HTTP 状态码和回退链路第一版只展示聚合分析，不直接作为全局筛选条件，避免在没有稳定查询字段时产生不准确的结果。

## 后端数据流

1. 接收时间、协议、模型、站点、Access Key 和来源筛选。
2. 在数据库层按时间和可下推筛选条件过滤 `ProxyUsageLogs`。
3. 将同一 `RequestId` 的记录归并为最终结果，同时保留完整尝试链路用于回退分析。
4. 统一规范化时间和历史字段。
5. 基于同一批最终结果构建核心趋势、分布、细分维度和延迟统计。
6. 基于完整请求链路构建回退分析。
7. 由后台统计队列和缓存统一返回 Dashboard，缓存键包含新增筛选条件。

Dashboard 返回结构增加：

- 来源分布
- Access Key 分布
- 协议分布
- 失败原因分布
- HTTP 状态码分布
- 回退链路分析
- 延迟分位数

所有新增结果与现有 `AppliedFilter` 使用同一筛选快照。

## 数据库兼容性

继续使用当前 SqlSugar 的增量建表和补列机制：

- 只增加字段和必要索引，不删除现有字段。
- 历史记录允许新字段为空。
- 历史记录继续参与统计。
- 旧日志无法识别时归入 `other`。
- 来源字段沿用已有默认值和已有分类。

如果按来源、错误分类或状态码查询需要额外索引，只增加与实际查询路径直接相关的索引。

## 前端结构

主要修改 [AnalyticsView.vue](frontend/src/views/AnalyticsView.vue) 和 [analytics.ts](frontend/src/api/analytics.ts)：

- 增加来源筛选状态和请求参数。
- 增加新增 Dashboard DTO 类型。
- 增加细分分析 Tab 和统一表格。
- 增加延迟分位数展示。
- 增加回退链路展示。
- 增加点击联动和筛选标签。
- 复用现有格式器、空状态、深色模式和响应式布局。

后端主要修改 [AnalyticsApiController.cs](src/AITool.Web/Controllers/Admin/AnalyticsApiController.cs)，并同步调整使用日志领域模型、写入 DTO 和日志写入入口。

- 来源、Access Key 和协议聚合。
- 来源筛选。
- `RequestId` 去重。
- 最终结果成功/失败口径。
- Token 和耗时口径。
- 错误分类和历史日志兼容。
- HTTP 状态码统计。
- P50、P95、P99 计算。
- 回退请求去重和链路聚合。
- Dashboard 缓存键包含新增筛选。

### 前端测试

- 新增 DTO 和数据映射。
- 细分分析 Tab 切换。
- 表格排序。
- 来源、Access Key、协议、站点和模型点击联动。
- 筛选标签删除和全部重置。
- 空数据状态。
- 延迟分位数和回退链路展示。
- 现有 Analytics 格式化和 8 个核心图表回归。

### 安全与视觉验证

- 验证列表和聚合结果不包含完整密钥。
- 验证不返回请求体、响应体、上游 API Key 或认证 Token。
- 验证 375、768、1280、1440 宽度布局。
- 验证深色模式。
- 验证前端测试、`vue-tsc`、生产构建和后端测试。
- 如环境没有浏览器自动化能力，明确报告未完成真实视觉交互验证，不虚报结果。
