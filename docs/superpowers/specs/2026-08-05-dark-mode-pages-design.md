# routes、codex 与 developer/invocations 暗色模式修复设计

## 背景

`routes`、`codex` 和 `developer/invocations` 页面在暗色模式下仍存在浅色主题硬编码，导致选中态出现浅色背景配白色文字、卡片和详情面板过亮、请求体与状态信息对比度不足等问题。调试工具页还包含客户端模拟器等嵌套组件，需要保持整体视觉一致。

## 目标

- 暗色模式下所有页面文字、背景、边框和状态标签保持清晰可读。
- 修复选中、悬停、拖拽、禁用、成功、等待和失败状态的对比度问题。
- 降低纯白或近白色面板在暗色页面中的刺眼程度。
- 保持亮色主题现有视觉和交互不变。
- 仅修改与本次主题问题直接相关的 `frontend` 文件，不覆盖现有 Analytics 修改。

## 方案

采用“语义化主题变量 + 页面硬编码替换”的方式：

- 在 `frontend/src/styles/main.css` 补充暗色和亮色共用的表面色、弱背景色、边框色及语义状态色变量。
- 在 `RoutesView.vue` 中将入口选中态、悬停态、拖拽态、优先级徽章、可用性徽章和禁用徽章改为主题变量。
- 在 `CodexView.vue` 中统一账号卡片、账号文本、计划标签、额度窗口、占位内容、导出工具栏和按钮状态的主题表现。
- 在 `DeveloperInvocationsView.vue` 中统一统计卡片、调用记录、状态标签、元信息、详情面板、请求/响应代码块和并发徽章的暗色配色。
- 在 `ClientSimulator.vue` 中复用主题变量处理端点展示和表单相关区域；保留代码输出区的深色代码块风格，但确保文字和边框对比度稳定。
- 不通过全局滤镜或大范围重构改变页面布局，不修改业务逻辑。

## 交互与状态

- 选中态使用低透明度主题蓝色背景配高对比度蓝色文字和边框。
- 普通面板使用 `--bg-card`，嵌套区域使用弱背景变量，代码块保持独立的深色表面。
- 成功、等待、失败状态继续使用绿色、橙色、红色，但在暗色模式中使用低透明度背景和较亮文字。
- 禁用内容降低透明度，但不降低到无法识别的程度。

## 验证

- 运行 `npm run type-check`。
- 运行 `npm run test`。
- 运行 `npm run build`。
- 复查差异，确保只涉及主题样式和相关设计文档，且没有覆盖工作区原有修改。
